# Compass-Gait Relaxed-Space Cycling-Signature Pipeline — NON-RUNNABLE/PARTIAL

> **NON-RUNNABLE orchestrator.** `run_pipeline.sh` exits before executing any
> stage. Stages 1–4 can be invoked individually, but the figure renderer also
> requires `data/compass_gait/barcode_H1_analytic_tgt025.csv`. No pipeline
> stage creates that analytic baseline, and it is not stored in the repository.

Stage inventory for reproducing the compass-gait row of the manuscript: a
learned encoder `E_theta` is trained on the relaxed hybrid semiflow, the
canonical limit-cycle rollout is embedded through the trained encoder, and
David Hien's `CyclingSignatures.jl` computes the `H_1` cycling signature over
a (cubical cover scale, sphere-bundle cover radius) grid. Figure rendering is
not self-contained until the separate analytic baseline is supplied.

The encoder is the generic Section-4 residual MLP
`E(x) = pad(x, d) + MLP(x)` initialised near the identity. It embeds the
**relaxed space** `X' = X union (G x [0,1])`, not the hybrifold
`M_H = X / ~` targeted by the original CHyLL of Teng et al. (2024). Training
follows Algorithm 1 of the manuscript: Phase I evaluates six terms
(`dyn`, `glue`, `conf`, `coll`, `seam`, `utb`), with the default objective
weighting `seam` by 1 and the legacy `utb` term by 0. Phase II freezes E and
F and trains the decoder D alone on boundary-masked reconstruction. See
`SPEC.md` for the full architecture and loss spec.

The full technical specification is in [`SPEC.md`](SPEC.md). This file is the
runbook.

## Dependencies

- **Python** environment with `torch`, `scipy`, `numpy`, `matplotlib`. On
  macOS MPS is used by default; falls back to CUDA then CPU. On Windows /
  WSL the config's `device = "mps"` is downgraded to CPU automatically.
- **Julia** (tested with 1.10), using the locked project and Manifest in
  `period_doubling/julia/`. That Manifest develops the repository-local
  `CyclingSignatures.jl/` package.

## How to run today

The partial [`run_pipeline.sh`](run_pipeline.sh) is deliberately disabled and
does not train or write artifacts. Invoke stages 1–4 individually using the
commands below. Stage 5 is documented for provenance, but it cannot run from
the current repository contents because its analytic input is absent.

### Step 1 — Train the relaxed-space encoder

```bash
python scripts/train_compass.py
```

Produces `runs/compass_gait/model.pt` after 120 Phase-I epochs (E + F on
`L_dyn + L_glue + L_conf + L_coll + L_seam`, with `L_utb` at zero weight)
and 150 Phase-II epochs (D alone on masked `L_recon`). Dataset is ~70k
`(x_i, x_{i+1})` supervised pairs; see `SPEC.md` for the exact loss and
sampling strategy.

### Step 2 — Evaluate decoded rollout vs ground truth

```bash
python scripts/evaluate_decoded_rollout_compass.py
```

This is the gate for whether the pipeline is real: loads the trained
model, simulates a held-out rollout from a perturbed limit-cycle IC, runs
both the round-trip `D(E(x))` and the semiflow rollout `D(F^k(E(x_0)))`
against the ground truth. Outputs phase-portrait and time-trace overlays
to `figures/compass_gait/fig_compass_decoded_rollout_*.png` and numerical
metrics to `data/compass_gait/report_decoded_rollout_metrics.txt`.

### Step 3 — Export encoded lift for cycling-signature input

```bash
# 5-impact canonical rollout
python "time series/cycling_signature/prepare_compass_cs_inputs_relaxed.py"

# 20-impact converged rollout (for the second heatmap panel)
python "time series/cycling_signature/prepare_compass_cs_inputs_relaxed.py" \
    --n_impacts 20 --suffix _relaxed_n20
```

Each invocation loads `runs/compass_gait/model.pt`, simulates the canonical
compass rollout (`time series/compass gait/simulate.py`), encodes arcs (at
`s = 0`) and bridges (50 interior `s ∈ (0, 1)` samples per impact) through
the trained encoder, writes `.npy` and `.csv` artifacts, and prints a
diagnostics report to
`data/compass_gait/report_relaxed*_encoder_diagnostics.txt`.

### Step 4 — Cycling signature in Julia

```bash
julia --project="period_doubling/julia" \
      "time series/cycling_signature/run_cycling_signature.jl" \
      --base continuous_lift_relaxed

julia --project="period_doubling/julia" \
      "time series/cycling_signature/run_cycling_signature.jl" \
      --base continuous_lift_relaxed_n20
```

The runner activates `period_doubling/julia/` explicitly and never resolves
the Windows-pathed `time series/cycling_signature/Manifest.toml`. The sweep
covers
`(boxsize, sb_radius) ∈ {0.30, 0.20, 0.10, 0.05} × {1, 2, 4}` and writes
`data/compass_gait/barcode_H1_relaxed{,_n20}.csv`.

### Step 5 — Render the heatmap figure

**NON-RUNNABLE from the current repository contents.** The renderer loads all
three sweep files unconditionally, including the absent analytic baseline:

- `data/compass_gait/barcode_H1_relaxed.csv`
- `data/compass_gait/barcode_H1_relaxed_n20.csv`
- `data/compass_gait/barcode_H1_analytic_tgt025.csv`

Once all three inputs have been supplied by a separately validated workflow:

```bash
python "time series/cycling_signature/plot_compass_rank_heatmap.py"
```

The command emits the main figure and the 3-panel appendix variant described
above.

## Regenerate figures only

If all three Julia sweep CSVs listed in step 5 already exist, the renderer can
be invoked directly:

```bash
python "time series/cycling_signature/plot_compass_rank_heatmap.py"
```

## One thing to know before reading the code

The encoder is a generic residual MLP on the full augmented state:

```
E_theta(x) = pad(x, d) + MLP_theta(x)
```

Its final layer is initialised near zero, so the initial map is close to the
identity in the unpadded coordinates. Nothing architecturally pins
`E_theta(x, 0)` after training; base-space injectivity and reconstruction are
training outcomes rather than hard constraints.
